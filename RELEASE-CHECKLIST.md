# Release checklist

## Before making a public preview

- Run the Windows GitHub Actions workflow from the intended commit; require green tests, lifecycle fixtures, runtime hash checks, recovery vectors and vulnerability scan.
- On a real Windows PC, test first install, start/stop, close/reopen with services running, compact window, upgrade from the previous manager, and uninstall while retaining user data.
- Test mining bridge install/start/stop/uninstall and the main uninstall's port-5555 rule removal, including declining UAC and retrying. Use an actual miner before claiming mining has been validated.
- Exercise wallet creation/import (including account 0 and a known second account), lock/unlock, backup/recovery and independent viewing tools. Validate any real-payment claim with a controlled low-value end-to-end transfer; otherwise keep it explicitly unverified.
- Exercise optional HTTPS/Tor with disposable identities before claiming either has been tested on this release.
- Review the release folder for user data and secrets; include runtime licenses, dependency notices and checksums. Confirm the ZIP actually contains the EXE and wallet-runtime.
- Enable GitHub private vulnerability reporting. Review repository permissions and branch protection. Do not upload local application data.
- Keep release status **Prerelease** and list what remains untested. Windows visual behavior, real mining and live payments were not validated in the preparation environment.

## Creating a release

1. Update ManagerVersion, app.manifest, CHANGELOG and validation notes together.
2. Push a tag matching `v<ManagerVersion>`, for example `v0.8.3-preview`.
3. CI builds/tests the Windows package. If successful, it creates a **draft prerelease** with a complete Windows ZIP and checksum file.
4. Review the draft, check the Windows test results and actual-user test results, and publish when ready. The workflow does not publish it automatically.

Release attachments, not GitHub's autogenerated source archives, are the runnable download. A checksum verifies bytes against the supplied checksum list; it is not a publisher signature.
